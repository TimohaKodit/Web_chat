# Web Chat

Веб-мессенджер с обменом сообщениями в реальном времени через WebSocket.

Пет-проект, который развивается до полноценного приложения: с авторизацией,
хранением истории в базе данных и деплоем на сервер.

## Стек

- **Python 3.12** + **FastAPI** — веб-фреймворк
- **uvicorn** — ASGI-сервер
- **WebSocket** — двусторонняя связь между сервером и клиентами
- **PostgreSQL** — хранение пользователей и истории *(в планах)*

## Возможности

- [x] Групповой чат: сообщение от одного клиента рассылается всем подключённым
- [x] Корректная обработка отключения клиента
- [x] JSON-протокол с типами сообщений
- [x] Имена пользователей и системные сообщения о входе/выходе

## Запуск

```powershell
# создать и активировать виртуальное окружение
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# установить зависимости
pip install -r requirements.txt

# запустить сервер
uvicorn app.main:app --reload --timeout-graceful-shutdown 3
```

Запускать из корня проекта — путь `app.main` считается относительно него.
`--timeout-graceful-shutdown` нужен, чтобы сервер не ждал открытые WebSocket-соединения
бесконечно при остановке по `Ctrl+C`.

После старта:
- `http://127.0.0.1:8000/` — интерфейс чата
- `http://127.0.0.1:8000/docs` — автодокументация API

## Как это работает

1. Браузер запрашивает `GET /`, сервер отдаёт `index.html`.
2. Пользователь вводит имя. Страница открывает WebSocket-соединение с `/ws`.
3. Первым сообщением клиент отправляет имя. Сервер запоминает связку
   `соединение → имя` в `ConnectionManager` и рассылает всем «X вошёл в чат».
4. Каждое следующее сообщение сервер дополняет именем автора и рассылает всем.
5. При отключении соединение удаляется из менеджера, всем уходит «X вышел из чата».

## Протокол

Все сообщения — JSON. Форматы клиент→сервер и сервер→клиент **разные**.

### Клиент → сервер

Первое сообщение после подключения — представление:
```json
{"user": "Вася"}
```

Все последующие — текст сообщения:
```json
{"text": "привет"}
```

### Сервер → клиенты

Поле `type` определяет, как клиент отображает сообщение.

| `type`    | Поля           | Когда                                   |
|-----------|----------------|-----------------------------------------|
| `message` | `user`, `text` | Обычное сообщение от пользователя       |
| `system`  | `text`         | Служебное событие: вход, выход          |

```json
{"type": "message", "user": "Вася", "text": "привет"}
{"type": "system", "text": "Вася вошёл в чат"}
```

Поле `user` проставляет сервер из своего хранилища — клиент не может подписаться
чужим именем в самом сообщении.

## Ручная проверка

Чек-лист, который должен проходить после любого изменения. Открыть страницу,
F12 → Console, дальше — команды из консоли браузера.

**Базовый сценарий**
- [ ] Две вкладки, разные имена. Сообщение из одной видно в обеих с именем автора.
- [ ] При входе второго участника в первой вкладке появилось «X вошёл в чат».
- [ ] Закрыть вторую вкладку — в первой появилось «X вышел из чата».

**Нарушение протокола** (сервер не должен падать, остальные клиенты не должны отваливаться)
```js
const t = new WebSocket(`ws://${location.host}/ws`);
t.onmessage = e => console.log("←", e.data);
```
- [ ] Первое сообщение без имени: `t.send(JSON.stringify({ foo: "bar" }))`
- [ ] Пустое имя: `t.send(JSON.stringify({ user: "" }))`
- [ ] Сообщение без `text`: `t.send(JSON.stringify({ user: "Тест" })); t.send(JSON.stringify({ x: 1 }))`
- [ ] Вообще не JSON: `t.send("просто строка")`
- [ ] Подключиться и сразу закрыть, не назвав имени: `t.close()`

Где смотреть результат: консоль uvicorn (нет трейсбеков) и DevTools → Network → WS
(соединения других вкладок живы).

## Известные ограничения

- Авторизации нет: имя не проверяется, любой может назваться кем угодно.
- История не сохраняется: после перезагрузки страницы сообщения пропадают.
- Один процесс: при запуске нескольких экземпляров сервера они не увидят
  сообщения друг друга.
